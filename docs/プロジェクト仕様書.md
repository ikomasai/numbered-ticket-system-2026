# プロジェクト仕様書

## プロジェクト概要

大学祭における整理券発券システム。企画の担当者（係員）が使用し、整理券の発券・呼び出し・状況確認を行う。

### 対象ユーザー

- **主な利用者**: 企画の担当者（係員）
- **一部利用**: お客さん（電子整理券の受け取り時のみ）

### 技術スタック

- **フロントエンド:** React Native (Expo) - Web版として使用
- **バックエンド:** Supabase
- **電子整理券確認ページ:** Supabase Edge Functions
- **使用言語:** JavaScript（TypeScript ではない）

### 認証

- 限定配布のため、ログイン機能は不要

---

## 機能要件

### 1. 企画管理

企画の登録・編集・削除を行う。

#### 企画の種類

| 種類 | 説明 |
|------|------|
| **時間枠定員制** | 時間枠ごとに定員があり、1枠あたりの時間と定員を設定 |
| **順次案内制** | 時間枠なし、空きが出次第案内する形式 |

#### 時間枠定員制のパラメータ

| パラメータ | 説明 |
|-----------|------|
| 企画名 | 企画の名称 |
| 企画場所 | 開催場所 |
| 定員 | 1枠あたりの定員数 |
| 1枠あたりの時間 | 分単位で設定 |
| 開催日 | 11/2, 11/3, 11/4 からチェックボックスで選択 |

#### 順次案内制のパラメータ

| パラメータ | 説明 |
|-----------|------|
| 企画名 | 企画の名称 |
| 企画場所 | 開催場所 |
| 1番号あたりの推定待ち時間 | 分単位で設定 |
| 開催日 | 11/2, 11/3, 11/4 からチェックボックスで選択 |

#### ステータス

| ステータス | 説明 | 変更方法 |
|-----------|------|---------|
| 未発券 | まだ発券を開始していない | 手動 |
| 発券中 | 発券を受付中 | 手動 |
| 発券停止中 | 一時的に発券を停止（トラブル対応等） | 手動 |
| 満員 | 定員に達した | **自動** |
| 発券終了 | 発券を終了 | 手動 / **自動**（時間枠開始時刻経過時） |

#### 時間枠の自動生成

- 開始時刻（10:00）〜終了時刻（19:00）を環境変数で管理
- 企画登録時に、設定した枠時間に基づいて時間枠を自動生成

#### 時間枠の自動終了ルール

- 時間枠の**開始時刻**を過ぎたら、その枠は自動で「発券終了」
- 例：11:20 現在 → 10:00〜11:00 枠は発券終了、11:00〜12:00 枠は発券中のまま

---

### 2. 発券

整理券を発行する。紙媒体と電子媒体の2種類に対応。

#### 発券フロー

1. 企画を選択
2. 日付を選択
3. 時間枠を選択（時間枠定員制の場合）
4. 発行媒体を選択（紙 / 電子）
5. 発券ボタンを押下
6. 結果を表示

#### 紙媒体発券

- 画面に以下の情報を表示
  - 整理番号
  - 時間枠（時間枠定員制の場合）
  - 企画名
  - 日付
- 係員が画面を見せながら、対応する番号の紙を手渡し

#### 電子媒体発券

- 専用QRコードを画面に表示
- お客さんがQRコードを読み取り
- Supabase Edge Function経由で確認ページを表示
- 整理券情報をローカルストレージに保存

#### 整理番号の採番ルール

| 企画種類 | ルール |
|---------|--------|
| 時間枠定員制 | 企画・日付ごとに通し番号（日付でリセット） |
| 順次案内制 | 企画・日付ごとに1から順番（日付でリセット） |

#### トランザクション処理

- 複数の担当者が同時に発券操作する可能性があるため、適切なトランザクション処理を実装
- 整理番号の重複を防止

---

### 3. 呼び出し

整理券の呼び出しを行う。現在版は機能重視のため、簡易的なものを実装。将来的に表示形式等変更予定。

#### 時間枠定員制の呼び出し

1. 企画を選択
2. 日付を選択
3. 呼び出す時間枠を選択
4. 確定ボタンを押下
5. 全画面で呼び出し表示（時間枠情報を表示）

#### 順次案内制の呼び出し

1. 企画を選択
2. 日付を選択
3. 現在の呼び出し番号・発券番号を確認
4. 何番まで呼び出すかを入力
5. 確定ボタンを押下
6. 全画面で呼び出し表示
7. Supabase Realtimeで他の画面にもリアルタイム反映

#### 呼び出し後の処理

- 呼び出し完了のステータス管理は不要
- キャンセルが起きた場合
  - 紙媒体：整理券を回収
  - 電子媒体：係員が整理番号をメモ

---

### 4. 発券状況の可視化

企画ごとの発券状況を確認する。

#### 時間枠定員制

- 枠ごとの発券数 / 定員
- 枠ごとの発券率（%）
- 全体の発券状況

#### 順次案内制

- 現在の発券番号
- 現在の呼び出し番号
- 推定待ち時間：`(次の整理番号 - 現在の呼び出し番号) × 1番号あたりの待ち時間`
  - 1番号あたりの待ち時間は係員が入力(係員は事前検証が必要)

---

### 5. 発券ログ

発券履歴を記録する。

#### 記録内容

- 発券日時
- 企画ID
- 日付
- 時間枠（該当する場合）
- 整理番号
- 媒体種類（紙 / 電子）

## 画面設計

### タブナビゲーション構成

| タブ | 機能 |
|------|------|
| 企画管理 | 企画の一覧・登録・編集・削除 |
| 発券 | 整理券の発行 |
| 呼び出し | 整理券の呼び出し |
| 状況確認 | 発券状況の可視化 |

### 1. 企画管理画面

#### 企画一覧

- 登録済み企画の一覧表示
- 企画名、種類、開催日、ステータスを表示
- 各企画に編集・削除ボタン
- 新規登録ボタン

#### 企画登録/編集画面

- 企画名入力（テキスト）
- 企画場所入力（テキスト）
- 企画タイプ選択（ラジオボタン：時間枠定員制 / 順次案内制）
- **時間枠定員制の場合**
  - 定員入力（数値）
  - 1枠あたりの時間入力（数値、分）
- **順次案内制の場合**
  - 1番号あたりの推定待ち時間入力（数値、分）
- 開催日選択（チェックボックス：11/2, 11/3, 11/4）
- 保存ボタン / キャンセルボタン

### 2. 発券画面

- 企画選択（プルダウン）
- 日付選択（プルダウン、選択した企画の開催日のみ表示）
- 時間枠選択（プルダウン、時間枠定員制の場合のみ表示）
  - 各枠の発券状況も表示（例：10:00〜10:30 [5/20]）
- 媒体選択（ラジオボタン：紙 / 電子）
- 発券ボタン
- **発券結果表示エリア**
  - 紙媒体：整理番号、時間枠、企画名、日付を大きく表示
  - 電子媒体：QRコードを表示

### 3. 呼び出し画面

- 企画選択（プルダウン）
- 日付選択（プルダウン）
- **時間枠定員制の場合**
  - 時間枠選択（プルダウン）
- **順次案内制の場合**
  - 現在の呼び出し番号表示
  - 現在の発券番号表示
  - 呼び出し先番号入力（数値）
- 確定ボタン
- **全画面呼び出し表示**
  - 時間枠定員制：「10:30の回」のような時間枠情報
  - 順次案内制：呼び出し番号

### 4. 状況確認画面

- 企画選択（プルダウン）
- 日付選択（プルダウン）
- **時間枠定員制の場合**
  - 時間枠ごとの発券状況一覧
  - 発券数 / 定員
  - 発券率（%）
  - ステータス
- **順次案内制の場合**
  - 現在の発券番号
  - 現在の呼び出し番号
  - 推定待ち時間

## データベース設計

### ER図（概念）

```
events (企画)
    │
    ├──< event_dates (企画開催日)
    │       │
    │       ├──< time_slots (時間枠) ※時間枠定員制のみ
    │       │       │
    │       │       └──< tickets (整理券)
    │       │
    │       ├──< tickets (整理券) ※順次案内制
    │       │
    │       └──< call_status (呼び出し状態) ※順次案内制のみ
    │
    └──< ticket_logs (発券ログ)
```

### テーブル定義

#### 1. events（企画テーブル）

| カラム名 | 型 | 説明 | 制約 |
|---------|-----|------|------|
| id | UUID | 主キー | PK, DEFAULT uuid_generate_v4() |
| name | TEXT | 企画名 | NOT NULL |
| location | TEXT | 企画場所 | NOT NULL |
| type | TEXT | 企画タイプ | NOT NULL, CHECK ('time_slot', 'sequential') |
| capacity_per_slot | INTEGER | 1枠あたりの定員 | time_slotの場合必須 |
| slot_duration_minutes | INTEGER | 1枠あたりの時間（分） | time_slotの場合必須 |
| estimated_wait_minutes | INTEGER | 1番号あたりの推定待ち時間（分） | sequentialの場合必須 |
| created_at | TIMESTAMP | 作成日時 | DEFAULT NOW() |
| updated_at | TIMESTAMP | 更新日時 | DEFAULT NOW() |

#### 2. event_dates（企画開催日テーブル）

| カラム名 | 型 | 説明 | 制約 |
|---------|-----|------|------|
| id | UUID | 主キー | PK, DEFAULT uuid_generate_v4() |
| event_id | UUID | 企画ID | FK → events(id) ON DELETE CASCADE |
| date | DATE | 開催日 | NOT NULL |
| status | TEXT | ステータス | DEFAULT 'not_started' |
| next_ticket_number | INTEGER | 次の整理番号 | DEFAULT 1 |
| created_at | TIMESTAMP | 作成日時 | DEFAULT NOW() |
| updated_at | TIMESTAMP | 更新日時 | DEFAULT NOW() |

**ステータス値**: 'not_started', 'active', 'paused', 'full', 'ended'

#### 3. time_slots（時間枠テーブル）

| カラム名 | 型 | 説明 | 制約 |
|---------|-----|------|------|
| id | UUID | 主キー | PK, DEFAULT uuid_generate_v4() |
| event_id | UUID | 企画ID | FK → events(id) ON DELETE CASCADE |
| event_date_id | UUID | 企画開催日ID | FK → event_dates(id) ON DELETE CASCADE |
| start_time | TIME | 開始時刻 | NOT NULL |
| end_time | TIME | 終了時刻 | NOT NULL |
| status | TEXT | ステータス | DEFAULT 'not_started' |
| current_count | INTEGER | 現在の発券数 | DEFAULT 0 |
| created_at | TIMESTAMP | 作成日時 | DEFAULT NOW() |
| updated_at | TIMESTAMP | 更新日時 | DEFAULT NOW() |

**ステータス値**: 'not_started', 'active', 'paused', 'full', 'ended'

#### 4. tickets（整理券テーブル）

| カラム名 | 型 | 説明 | 制約 |
|---------|-----|------|------|
| id | UUID | 主キー | PK, DEFAULT uuid_generate_v4() |
| event_id | UUID | 企画ID | FK → events(id) ON DELETE CASCADE |
| event_date_id | UUID | 企画開催日ID | FK → event_dates(id) ON DELETE CASCADE |
| time_slot_id | UUID | 時間枠ID | FK → time_slots(id), NULL許可 |
| ticket_number | INTEGER | 整理番号 | NOT NULL |
| medium_type | TEXT | 媒体種類 | NOT NULL, CHECK ('paper', 'digital') |
| qr_token | TEXT | 電子媒体用トークン | UNIQUE, NULL許可 |
| issued_at | TIMESTAMP | 発券日時 | DEFAULT NOW() |
| created_at | TIMESTAMP | 作成日時 | DEFAULT NOW() |

#### 5. call_status（呼び出し状態テーブル）

| カラム名 | 型 | 説明 | 制約 |
|---------|-----|------|------|
| id | UUID | 主キー | PK, DEFAULT uuid_generate_v4() |
| event_id | UUID | 企画ID | FK → events(id) ON DELETE CASCADE |
| event_date_id | UUID | 企画開催日ID | FK → event_dates(id) ON DELETE CASCADE |
| current_call_number | INTEGER | 現在の呼び出し番号 | DEFAULT 0 |
| updated_at | TIMESTAMP | 更新日時 | DEFAULT NOW() |

**UNIQUE制約**: (event_id, event_date_id)

#### 6. ticket_logs（発券ログテーブル）

| カラム名 | 型 | 説明 | 制約 |
|---------|-----|------|------|
| id | UUID | 主キー | PK, DEFAULT uuid_generate_v4() |
| ticket_id | UUID | 整理券ID | FK → tickets(id) ON DELETE CASCADE |
| action | TEXT | アクション | NOT NULL, DEFAULT 'issued' |
| performed_at | TIMESTAMP | 実行日時 | DEFAULT NOW() |
| details | JSONB | 詳細情報 | NULL許可 |

## API 設計

### Supabase Client API

#### 企画管理

| 関数名 | 説明 |
|--------|------|
| selectEvents() | 全企画を取得 |

|--------|------|

| 関数名 | 説明 |
|--------|------|

| チャンネル | 説明 |
|-----------|------|

## セットアップ手順

1. リポジトリをクローン
   ```bash
   git clone [repository-url]
   cd numbered-ticket-system-2026
   ```

2. 依存関係をインストール
   ```bash
   npm install
   ```

3. 環境変数を設定
   ```bash
   cp .env.example .env
   # .env ファイルを編集
   ```

4. Supabaseプロジェクトを作成し、マイグレーションを実行
   ```bash
   supabase db push
   ```

5. Edge Functionsをデプロイ
   ```bash
   supabase functions deploy ticket
   ```

6. アプリを起動
   ```bash
   npm start
   ```

## 注意事項

### トランザクション処理

- 発券時は必ずトランザクション処理を行い、整理番号の重複を防止
- 複数端末からの同時発券に対応

### 自動ステータス更新

- 時間枠の開始時刻経過時の自動終了は、アプリ側で定期チェック or Supabase Functionで実装
- 満員時の自動ステータス変更は、発券時のトリガーで実装

### リアルタイム更新

- 順次案内制の呼び出し番号は、Supabase Realtimeで全端末に即時反映
